AEx1 条件激活

常规级创作者阅读约 13 分钟
适用于 Stitchwork 0.9.1 · 更新于: 2026-10-19

基础知识 · 附加篇
让资源包跟着游戏自己开关。
它可以根据你所在的房间、装备的纹章，或你已经经历过的某个事件来判断。
没有任何条件的资源包，只要你启用它，它就生效，这也是大多数情况下最合适的做法。

你将学会：为资源包设置条件、看懂条件抽屉里的括号和指示灯、选择正确的重新检查时机，以及排查为什么资源包没有按预期生效。

条件有什么用？

添加条件后，资源包只会在游戏状态符合要求时启用。常见用途包括：

  • 氛围包——例如只在灰沼播放自定义音乐，一离开该区域便恢复原版。
  • 与纹章绑定的外观切换——女巫纹章专用皮肤，仅在装备女巫纹章时出现，卸下纹章后自动恢复原外观。
  • 里程碑奖励——击败某个首领，或者某个游戏标记旗帜被设置后，自动启用新的皮肤或资源。

整个过程都无需编写代码。在资源包管理器的条件抽屉里，一次添加一个条件就行。要打开抽屉，点击资源包卡片底部按钮栏里的滑块按钮，抽屉会在卡片下方展开。再点一次同一个按钮就能收起。抽屉里没有“完成”按钮。

设有条件并且已启用的资源包，卡片会带一圈橙色边框。卡片的状态行会把条件写成一句话，例如“当纹章 是 收割者且织针 至少是 辉光织针时”。这句话只写出第一组条件，后面的“· 或另外 1 组”表示还有几组其他条件。句子前面有一个小圆点，条件满足时它会变成实心。

抽屉里的条件只存在你自己的游戏里，不跟着资源包走：Stitchwork 把它们保存在自己的设置里。资源包本身只能以子集的形式自带条件，这是一项预览功能，本页末尾有介绍。创作者如果希望整个资源包按条件启用，会在资源包的 README 里写明，每位玩家照着设置一次就行。

条件逻辑怎么理解——看括号，不用学布尔逻辑

每个资源包在你的游戏里都有一组条件，抽屉会自动用括号把它们分好组，因此你只需要按图理解：

  • 同一个括号里的条件必须全部成立（AND / 且）。
  • 不同括号之间互为备选，只要任意一个括号成立即可（OR / 或）。

这就是全部规则。（“场景包含 Greymoor 且纹章是女巫” 或 “场景是 Bone_East_12”——这就是两个括号，满足任意一个即可。）这种逻辑的学名叫做析取范式（Disjunctive Normal Form），不过完全不用记这个名字。

控件

  • 添加条件会在最下面加一个新条件。新条件以且接到最后一组里。
  • 两个条件之间的且 / 或按钮表示它们怎么连接，点一下就能切换。
  • 条件末尾的 × 用来删除这个条件。
  • 抽屉底部的全部清除会删除所有条件，要点两次才会执行。

看懂括号

  • “且”优先结合。两个“或”按钮之间的所有条件组成一组，由一个括号括起来。
  • “且”按钮位于所在组的括号上；“或”按钮在最左侧，旁边有一条横贯抽屉的线。
  • 只有一个条件的组不画括号。

一个条件，就是一句话

每个条件都是一个小方框，左边缘有一盏指示灯。它读起来就是一句话，分两行显示：

  • 第 1 行：判断对象、比较方式，以及 ×。
  • 第 2 行：要比较的值。

点击判断对象或比较方式，按钮下方会弹出对应的列表。判断对象的列表分四组：地点（场景、区域）、剧情（幕、已击败的首领）、大黄蜂（纹章、织针、能力、面具、灵丝轴、丝之心、钢铁之魂、存档数据）和绣补（资源包）。每个判断对象右边都有一句简短提示，说明它读取的是什么。

判断对象比较方式值
场景是、不是、包含、不包含手动输入的场景名称，不区分大小写。点击当前房间会填入你现在所在的房间。
区域是、不是从列表中选择一个地图区域，列表带有搜索功能。过场动画期间，区域仍算作播放前所在房间的区域。
幕是、不是、小于、至多是、大于、至少是第一幕、第二幕或第三幕。
已击败的首领包括、不包括从列表中选择首领，列表带有搜索功能。这个存档已经击败的首领旁会标着“已击败”。
纹章是、不是从列表中选择：猎手、收割者、漫游者、萨满、建筑师、野兽、女巫、受诅咒或监狱模式。你当前装备的纹章旁会标着“已装备”。
织针是、不是、至少是、至多是从列表中选择：织针、尖锐织针、辉光织针、蜂钢织针或苍白蜂钢织针。你当前的织针等级旁会标着“当前”。
能力包括、不包括从列表中选择技能和披风，列表带有搜索功能。大黄蜂已经掌握的能力旁会标着“已习得”。
面具是、不是、小于、至多是、大于、至少是一个数字：她满血时的面具数量。
灵丝轴和面具相同一个数字：她的灵丝轴有多长。
丝之心和面具相同一个数字：她拥有的丝之心数量。
钢铁之魂已启用、已停用没有值：判断这个存档是不是钢铁之魂存档。
存档数据取决于字段（见下文）从列表中选择游戏存档数据（PlayerData）里的一个字段。列表带有搜索功能。
资源包已启用、已停用从列表中选择另一个资源包。列表里每个资源包旁都会显示“启用”或“停用”。适合只在主资源包启用时才生效的扩展包。

场景用是时，必须和完整名称一致。包含只需匹配名称的一部分，所以就算游戏给场景名加了后缀，也照样能匹配上。

只要游戏里有对应的文本，首领、能力和区域的名称就会以界面语言显示。如果某个条件是这个版本的 Stitchwork 读不懂的（比如来自更新版本的某个首领），它会被当作不成立，那一行也会写明原因。

不是、不包含、不包括和已停用会把单个条件反过来——“除了这里，哪里都生效”。它们只会取反这一个条件，不会取反整个括号。

游玩时，抽屉会显示什么

抽屉每秒读取两次游戏状态。它按抽屉里当前显示的条件来判断，所以改完条件、还没点“应用”，你就能先看到结果。

  • 成立的条件会点亮指示灯，方框也会变成青绿色。
  • 一组里的条件全部成立时，这组的括号会变成一条实心的青绿色丝线。
  • 抽屉顶部生效条件旁边的标签会显示当前生效或当前未生效。
  • 当游戏让某个条件成立时（比如在长椅上换了纹章），这个条件会闪一下，接着丝线填满括号，标签也会跳一下。

减少动画（设置 › 常规）可以关掉这些效果。

把鼠标指向抽屉的各个部分，就能看到原因：

  • 指示灯会显示“当前满足”，或者游戏现在读到的值，例如“不满足：当前纹章 是 收割者”。
  • 括号会显示组内有几个条件成立，例如“已满足 1/2：须全部满足”。
  • 标签会指出是哪一组让资源包生效。如果没有一组成立，它会指出最接近的那一组，以及其中有几个条件成立。

更多空间：把条件抽屉分离出来

条件抽屉可以移到资源包管理器旁边的独立面板里：点击抽屉顶部的箭头按钮（分离）即可。之后，点击任意卡片上的滑块按钮，都会在这个面板里打开该资源包的条件。这个选择对所有资源包都有效，重启游戏后也会保留。

面板一次只显示一个资源包，也就是你点了滑块按钮的那个。顶部一栏显示资源包的封面、名称和状态；资源包关闭时，还会显示资源包已关闭标记。里面的控件和抽屉里的一样，只是空间更大。如果资源包带有子集，而屏幕又足够宽，子集会单独占一列。

和在抽屉里一样，你的修改要等点击资源包管理器底部的应用后才会生效。面板底部的一行字会提醒这一点；这个资源包有尚未应用的修改时，这行字会变成琥珀色。把鼠标指向这行字，应用按钮就会亮起来。

想放回抽屉，点击面板顶部一栏右端的箭头（放回）。底部的关闭会关掉面板，你的修改仍然保留。面板可以拖到任何位置；每次重新打开，它都会回到资源包管理器旁边。

资源包什么时候重新检查条件——“检查”选项

条件只有在重新进行判断时才会产生作用。抽屉底部附近的检查一行，可以在两个选项中选一个：

  • 切换房间时——每次载入新房间，Stitchwork 都会检查一遍条件。几乎不占资源，适合判断你在哪里（场景、区域）或其他资源包（判断对象资源包）的条件。
  • 实时——游玩过程中，Stitchwork 每 2 秒检查一次条件。当条件可能不经过房间载入就发生变化时，就用这个选项，例如切换纹章、升级织针、击败首领、某个标记在房间内发生变化。

这个选项只影响什么时候检查，不会影响检查的结果。例如，一个只判断场景的条件，即使选择实时也依然能正常工作，只不过会比实际需要多检查几次。

抽屉也会帮你把关。当你选择一个可能在房间内变化的判断对象时，它会自动把资源包设为实时。这些判断对象是幕、已击败的首领、纹章、织针、能力、面具、灵丝轴、丝之心和存档数据。如果你又改回切换房间时，抽屉会显示一条警告：“剧情和大黄蜂的条件可能在房间内变化；‘实时’能及时捕捉。”

PlayerData——万能钥匙

存档数据条件会按名称读取游戏当前的存档数据（PlayerData）中的一个字段。因此，它是适用面最广的条件：念珠、收集物、剧情进度、区域标记……只要游戏记录了，就可以判断。与此同时，它也是最需要小心的一种，因为字段名称来自游戏本身，而不是 Stitchwork。

字段列表会列出所有真/假、数字或文本类型的字段，并标出各自的类型。在搜索框里输入名称的一部分，就能缩小列表范围。可用的比较方式取决于字段类型：

  • 真/假字段可以用为真或为假——很适合判断“事情是否已经发生”这类标记。
  • 数字字段可以用是、不是、小于、至多是、大于或至少是，然后输入一个数字：geo 至少是 100。
  • 文本字段可以用是或不是，然后输入文本。
  • 不要相信未经确认的字段名。存档字段名称可能随着游戏版本发生变化，而从《空洞骑士》沿用下来的名字尤其容易误导。例如，在《丝之歌》中玩家操控的就是大黄蜂，因此《空洞骑士》中类似 defeatedHornet 这样的字段，绝不是“击败当前 Boss”的标记。字段列表只显示名称，不会告诉你每个名称的含义。要找到正确的字段，请打开文本标签页的编辑器面板，再看其中的（游戏存档）标记栏。它会按真实名称列出游玩时发生变化的 PlayerData 标记。在那里关闭仅剧情，就能看到全部标记。请使用这份列表里的名称，不要凭记忆，也不要照搬为其他版本写的攻略。
  • 字段名写错不会报错。错误的字段只会被悄悄当作 false。抽屉的列表能避免拼错，但手动编辑的设置文件里的名称，或者游戏更新后已经删掉的名称，照样会失效。它不会报错，结果就是资源包始终不会启用，看起来和逻辑写错完全一样。因此，在怀疑逻辑问题之前，先确认字段名称是否正确。

示例

下面这些例子，在抽屉中都只需要一两个条件即可完成。

仅在一个房间内生效——给 Bone East 的某一个房间换配色：

  • 场景 是 Bone_East_12（站在那个房间里点击当前房间，就会自动填入名称）
  • 检查：切换房间时。

仅装备女巫纹章时生效——切换纹章后大约 2 秒内更新：

  • 纹章 是 女巫（从列表中选择）
  • 检查：实时。

在圣堡工厂全区域生效，但必须装备猎手纹章——两个条件放在同一个括号：

  • 场景 包含 Under（圣堡工厂的房间名为 Under_01、Under_02 等）
  • 且（新条件默认以“且”连接，这里什么都不用点）
  • 纹章 是 猎手
  • 检查：实时。

位于灰沼，或者某个剧情标记已经开启——两个条件放在不同括号：

  • 第 1 组：场景 包含 Greymoor
  • 或（第二个条件默认以“且”连接，点一下那个“且”，把它改成“或”）
  • 第 2 组：存档数据 act2Started 为真
  • 检查：实时。

资源包没有生效时

请从上往下逐行对照下表。前几行先检查外层：开关和应用。最后几行再检查逻辑。

现象检查
资源包始终不启用看看资源包卡片上的开关；停用的卡片颜色会变暗。设了条件的资源包如果被停用，就不会判断任何条件。
修改后什么都没变点击应用。抽屉底部也写着：“更改需点击‘应用’后生效。”关闭抽屉并不会自动应用更改。
不知道是哪个条件不成立打开抽屉，看指示灯。熄灭的指示灯表示这个条件不成立。把鼠标指向指示灯，提示文字会告诉你游戏现在读到的是什么。
场景条件始终不成立使用场景的真实名称。状态角标（左下角）的第二行会显示当前场景名称。那里没法复制，所以要照着显示的拼写一字不差地输入，尤其是用是做精确匹配时。或者，站在那个房间里点击当前房间。
场景 是条件在某些房间失效一旦场景名称多了你没写进去的后缀，是就会失效。不确定时，优先使用包含。
新条件永远不匹配，或者匹配所有场景把值填上。新添加的条件默认是场景 是，没有值，它永远不会匹配。空的包含会匹配所有场景。请把每个条件都填完整，或者用 × 删掉它。卡片上的句子会用 … 表示空值。
资源包要到下一个房间才变化把检查设为实时：参见资源包什么时候重新检查条件。
手动编辑的设置文件里，纹章匹配不上在抽屉里，纹章是从列表中选的，所以不会拼错。在 Stitchwork 的设置文件里，纹章的值可以写游戏里的英文名称，也可以写游戏内部的 ID。有三个 ID 和名称不一样：萨满（Shaman）是 Spell，建筑师（Architect）是 Toolmaster，野兽（Beast）是 Warrior。
想知道资源包什么时候切换查看日志。每当条件资源包启用或停用时，BepInEx/LogOutput.log 里都会多一行，例如 [PackManager] 'My Pack' condition → active (scene='Bone_East_12')。这一行也会给出场景的真实名称。
存档数据条件始终不成立，也没有报错首先怀疑字段名：参见PlayerData——万能钥匙里的注意事项。
仍然找不到原因先删除所有条件，让资源包保持始终启用，确认资源本身没有问题；然后一个一个地把条件加回去。加上哪个条件后资源包失效，问题就出在哪个条件上。

每个资源包都要从两方面测试。载入存档，进入目标场景（或达到目标状态），确认资源包能够启用；再确认在其他情况下不会误触发。走到不同地方时，指示灯和标签会告诉你哪些条件成立。

子集：资源包自带的条件（预览）

说明

子集目前还是预览功能，文件夹结构和文件格式以后仍可能改变。

上面讲的内容都只存在你自己的游戏里。而子集保存在资源包里：它是资源包的一部分，只在自己的条件成立时才显示。比如收割者纹章版本的披风，或者只剩一格血时的破损造型，都可以直接放进资源包，每位玩家拿到就能用，不需要任何设置。

把每个部分放进资源包里的 Sets/<name>/，内部结构和资源包一样（Sprites/、Spritesheets/、Sounds/、Text/ 以及其他文件夹）：

MyPack/Stitchwork/
  Sprites/…                  ← the pack's own files
  Sets/Reaper/Sprites/…      ← only while Hornet wears the Reaper crest
  Sets/LowHealth/Sprites/…   ← only at one mask of health

用内置名称命名的文件夹，不需要任何其他文件就能生效。内置名称有：九个纹章，即 Hunter（猎手）、Reaper（收割者）、Wanderer（漫游者）、Shaman（萨满）、Architect（建筑师）、Beast（野兽）、Witch（女巫）、Cursed（受诅咒）、Cloakless（监狱模式）；以及 LowHealth（只剩一格血）、FullHealth、TitleScreen 和 Always。

如果想用自己起的名字，或者要设定顺序，就在 pack.json 旁边加一个 conditions.json：

{
  "conditions": { "Hurt": { "playerData": "health <= 2" } },
  "sets": [
    { "name": "Reaper", "when": "Reaper" },
    { "name": "Hurt",   "when": "Hurt" }
  ]
}
  • 两个子集同时启用时，列表中靠上的那个优先，和资源包列表里靠上的资源包优先是一个道理。"sets" 里列出的子集，优先于没有列出的文件夹子集。如果某个文件所有子集都没有提供，就显示资源包本身的文件。
  • 子集启用或停用时，会重新加载资源包的美术资源，和带条件的资源包一样。子集里的每个文件都会重新载入，所以子集里只放会变化的文件就好。每次日志里都会多一行 [RuleSets]。
  • 体检功能会检查 conditions.json 和各个 Sets/ 文件夹。如果某个子集几乎装下了整个资源包，或者子集里的文件和资源包本身的文件一模一样，体检会给出警告。
  • 代码模组可以为子集发布条件，详见面向代码模组的 API。

在资源包管理器里，资源包的条件抽屉有一个子集区域。每个子集那一行会显示它包含的文件，例如“22 张贴图 · 2 段音频”；卡片上那一行则会显示“已启用 n/m 个子集”。

  • 试用（子集那一行上的眼睛图标）会无视条件，立即显示这个子集，直到你关闭抽屉为止。前提是资源包已经启用并且已经应用。
  • 子集那一行如果出现琥珀色的“共用 n 个”标签，说明它有这么多文件也在更靠上的子集里，而且两者可能同时启用。把鼠标指向标签，就能看到哪个子集优先。
  • 如果某个子集的条件永远不可能满足，它那一行会写明，这个子集也会一直保持关闭。
  • 在你的条件下，玩家可以给子集再加上自己的条件。
  • 对于放在全局资源包文件夹里的资源包，点击铅笔按钮会在抽屉里打开 conditions.json 的编辑器，编辑器里的箭头可以把子集在列表中上移或下移。点击保存即可写入文件。
