B1 开始制作资源包

入门级创作者阅读约 10 分钟
适用于 Stitchwork 0.9.0 · 更新于: 2026-10-20

精灵图 · 面向创作者
你的第一次动手实践。
导出游戏中真实的一帧精灵图动画，重新绘制，保存文件，然后在游戏里实时查看效果。
再把你的美术整理成一个可以分享的资源包。
约 10 分钟，只需要任意一款 PNG 编辑器。
这个流程体感不应该像三百六十五里路呀~

你将学会：
从头到尾替换一张精灵图——找到它、编辑它、片刻之后就在游戏中看到效果——再把零散的修改整理成一个可开关的资源包。
游戏里的其他精灵图，也都和你的第一次修改是同样的流程。

开始之前：先读完模块 A，这样文件夹的结构和规则就不会显得莫名其妙。
确认 Stitchwork 已经运行，载入一个游戏存档，并让大黄蜂出现在画面中。

我们会把大黄蜂待机动画中某一帧的披风改成亮蓝色。
本教程使用的是当前正式版游戏中的真实名称——请用你的身份卡（第二步）核对一下。

先提醒一句，再决定投入多少时间：本页介绍的是单张精灵图的工作流，足够应付道具、姿势调整和小幅修图。如果要重绘整段动画，还有一套专门的动画工作流：所有工作流的全貌见选择工作流。

第一步——打开动画模式

打开图形页面：按 3（顶排数字键；你这个版本的具体按键请参考热键）。也可以把鼠标移到屏幕顶部边缘，点击图形标签页。这时会打开两个面板：左边是预览播放，右边是资源库。如果按下没有反应，说明某个文本输入框还占着键盘焦点，或者 Stitchwork 正在给 DebugMod 的界面菜单让位。

在资源库的模式行中选择动画。这里就是整个 tk2d 动画世界。“或选择已在本次游戏中播放过动画的对象：”下方的列表，会列出场景载入以来播放过动画的每一个对象。每一行都有 GameObject 名称、一张缩略图，以及一行 clip · frame/count。列表上方的游戏场景内选取对象则可以让你直接在画面中点选对象（B2）。

第二步——找到大黄蜂（她的文件名叫“Knight”）

在对象列表中，大黄蜂这一项的名称如下——它固定排在最顶上：

Hero_Hornet(Clone)

点击它。资源库会切换到大黄蜂的动画片段：最上面是选中的那一行（“Hero_Hornet(Clone) 已选中”，带有更换和选取按钮），然后是搜索动画、排序行、动画列表，以及列表下方的控制台。在搜索动画中输入 idle，然后点击 Idle 这一行。大黄蜂会播放这段动画并停在第一帧，所以你不需要让她一直站着不动。（按暂停，也就是 Insert，就能把她的动画交还给游戏。）

选择帧要用预览播放面板：在帧条的刻度上点击或拖动，或者使用上一帧和下一帧（PageUp / PageDown）。控制台里的身份卡会用一行显示这一帧的路径，里面就是三个以后会反复遇到的名称：

Knight › atlas2 › idle0000 #<sprite number>
  • 集合——Knight
  • 材质（图集）——atlas2
  • 精灵图——idle0000

没错，是 Knight，而不是 Hornet。《丝之歌》沿用了《空洞骑士》的内部命名，因此大黄蜂的精灵图实际上放在名叫 Knight 的集合里。几乎所有人初见都会在这里踩坑——现在你不会了。（更多类似的内部别名可参考术语表。）

这些名字请始终以身份卡实际显示为准，无需也不建议死记硬背。 今天这个待机动画使用的是 atlas2，但图集编号可能会随着游戏版本变化。身份卡永远是正确的，而任何教程都可能会随着下一次更新而过时。

第三步——一键开始编辑

在控制台的此精灵图分组中，点击编辑（从原版新建）。这个按钮会一次性完成三件事：把原版的这一帧导出到磁盘，将其复制到你的工作区文件夹，再用你的图片编辑器打开 PNG（系统默认程序，或者你在总览面板中设为图像编辑程序的那个）。文件生成之后，同一个按钮会变成编辑（打开已有文件）。现在你看到的，就是游戏当前正在绘制的那张图片，而且游戏已经开始实时读取你即将编辑的文件。

如果打开的是图片查看器，而不是你的编辑器，请打开总览面板（按 2），把图像编辑程序设为你用的程序。留空则继续使用系统默认程序。在 Windows 上，如果你设置的编辑器已经打开，点击编辑会把它的窗口切到游戏前面。

文件放到了你的工作区文件夹：也就是游戏根目录下、与 Packs/ 并列的 Stitchwork/ 文件夹。它非常适合快速试验，模组管理器更新也不会碰它。除非某个已启用的资源包里也有同一张精灵图的文件，否则这里的文件都会生效（资源包在第六步讲）。

<Game folder>/Stitchwork/Sprites/Knight/atlas2/idle0000.png

如果希望一次拿到整段动画中的所有帧，请看第七步。

第四步——开始绘制

把披风改成亮蓝色（#0080FF）。大黄蜂原本的披风是红色的，换成蓝色，变化一眼就能看出来。只改披风的颜色：透明度、背景和精灵图的其他部分都保持不变。细节优化以后再说，先用这个明显的颜色变化确认你的替换图已经载入。

保存时请遵守三个规则：

  • 尺寸保持不变或更大，绝不能更小。更大的替换图完全没问题——Stitchwork 会自动扩展图集（而额外空间的位置由锚点控制）。更小的文件会被拉伸到原来的尺寸，画面会变糊。
  • 保留 Alpha 通道。本来透明的区域仍应保持透明，不要把图片合并到背景上。
  • 保存为 PNG 格式。JPG 格式没有 Alpha 通道，无法保存透明度，而且压缩会让每条边缘都出现脏边。

直接覆盖保存即可——路径和文件名都不要改。

你的美术边缘有白色斑点？Clip Studio Paint 在保存 PNG 时，会把透明像素的底色存成白色。游戏绘制你的美术时，会把这些藏起来的白色混进美术的边缘。清理精灵图边缘（CSP 修复）会在游戏里去掉这些斑点，你的文件也不会有任何改动。

这个开关在设置 › 渲染中（按 0），默认开启。想清理文件本身，请使用资源包体检（第六步）。问题自查讲解了这些斑点出现的原因，以及怎样在绘图软件里把它们减淡。

第五步——实时查看效果

切回游戏。片刻之后，文件监视器会检测到修改，并把你的图片合成到实时图集中。你编辑的那一帧待机动作里，披风现在应该已经从红色变成了亮蓝色。

编辑 PNG → 保存 → 文件监视器 → 重载 → 合成 → 游戏显示（无需重启）

如果你已经把动画交还给游戏，而她正好跳起来或者离开了画面，就来回走几步，等她重新进入待机状态——因为你只修改了这一帧，所以效果也只会出现在这一帧上。

斗篷还是红色的吗？先看看屏幕底部中间的消息。已应用表示游戏已经绘制了你的文件。如果显示部分应用或未应用，游戏没有绘制的每个文件都会标为“尚未绘制”。对于标为“尚未绘制”的文件，要么是文件名或文件夹对不上，要么是这个集合没有在当前场景中载入。接下来，请按出现异常情况时中的三个排查问题逐一检查。原因几乎总是路径，或者精灵图系统。

第六步——做成真正的资源包

现在，你修改后的精灵图仍然位于工作区文件夹中：无法关闭，也无法分享。下面把它升级成真正的资源包——一个可以由资源包管理器开关的独立文件夹：

  1. 在全局资源包文件夹 <Game folder>/Packs/ 下新建一个资源包文件夹，里面再建一个 Stitchwork/ 子文件夹——和 Thunderstore 安装的结构相同：
    <Game folder>/Packs/my-hornet-skin/Stitchwork/
  2. 在里面重新建立资源路径，并把你的 PNG 移过去。下面是同一帧分别在导出、工作区文件夹和你的资源包里的路径，都从游戏文件夹算起：
                   Stitchwork/Dumps/Sprites/Knight/atlas2/idle0000.png
                     Stitchwork/Sprites/Knight/atlas2/idle0000.png
Packs/my-hornet-skin/Stitchwork/Sprites/Knight/atlas2/idle0000.png
    （Stitchwork/ 下面的目录结构与工作区文件夹完全一致。）
  3. 回到游戏，打开资源包面板（也就是资源包管理器）：按 1，点击左下角的状态角标，或者点击资源包标签页。每个资源包都是一张卡片。你会看到新的资源包已经出现在列表里——不过和所有新建的资源包一样，它默认是关闭的。点击卡片上的开关，然后点击面板底部的应用。列表里没有？点击顶部的重新扫描。

每个管理器档案都能看到 Packs/ 这个文件夹，更新也永远不会碰它。放在 BepInEx/plugins/ 下的资源包文件夹也照常工作：Thunderstore 安装的内容就放在那里。资源包面板和图形面板会轮流显示：最后打开的那个会留下来。

现在，亮蓝色的披风是从你的资源包里载入的了。你可以调整这个资源包的优先级，也可以把它分享给朋友。

推送和拉取

工作区文件夹是你修改素材的地方，资源包是你拿去分享的成品。总览面板（按 2）里有两个按钮，负责在两者之间复制文件。用过 Git 的话，这两个名字的方向和 Git 一样：

  • 推送：把你的成果送进资源包。
  • 拉取：把资源包里的文件取回工作区文件夹。

第一次推送之前：先建好资源包文件夹，再在总览面板的目标资源包：里选中它。

推送会把工作区文件夹里的精灵图、整图、音效、视频、文本、字体和颜色规则文件，按相同的文件夹结构复制进资源包。资源包里同名的文件会被覆盖。推送永远不会删除资源包里的文件。按钮下方会有一行结果统计：新增了多少、覆盖了多少、跳过了多少 _WIP 文件。

推送是复制，不是移动。推送之后，工作区文件夹里还留着那张蓝色精灵图，于是同一张图有了两份：

  • 资源包启用时，资源包里的那份优先。所以每次修改后都要重新推送，或者在制作期间先把资源包关掉。
  • 关掉资源包，你可能还是看到蓝色。这时显示的是工作区里的副本，而不是原版的红色披风。想确认资源包开关的效果，请先把工作区里的副本移出 Stitchwork/Sprites/，再禁用其他替换了这张精灵图的资源包。

拉取方向相反，从资源包到工作区文件夹：

  • 拉取（合并）会把资源包的文件复制到你自己的文件旁边。工作区文件夹里同名的文件会被覆盖。
  • 拉取（替换）会先清空工作区文件夹，再复制。它需要你再点一次确认。

想在别人的资源包基础上开始修改，拉取也很好用。Customizer 皮肤同样可以拉取，但不能推送进去：Stitchwork 永远不会修改 Customizer 皮肤的文件夹。

名称以 _WIP 结尾的文件夹，是你的画布工作区。推送和拉取都不会复制它们，拉取（替换）也不会删除它们。总览文件列表里的彩色圆点表示每个文件的状态：已加载、待加载或在磁盘。

分享之前

分享之前，还有两项可选的收尾工作。资源包卡片上的听诊器按钮（鼠标指向时提示“对此资源包进行体检：生成并打开体检报告”）会给资源包做一次体检，并打开体检报告。如果报告发现了边缘偏浅的 PNG（见第四步），资源包管理器会给出先备份，再清理这个选项。它会先把每个要修改的 PNG 复制到你工作区文件夹下的 Backups/clean-edges/，然后清理这个文件。清理过的文件，无论玩家怎么设置，都不会再出现斑点。

把一张 1280 × 400 像素的 cover.png 放进资源包的 Stitchwork/ 文件夹，资源包管理器就会把它显示在资源包的卡片上（资源包封面）。

手上有 Customizer 皮肤？

已经装在游戏 …_Data/Mods/Customizer/ 文件夹下的皮肤会被自动识别，并出现在资源包面板里，卡片上带有一个衣服图标（鼠标指向时提示“Customizer 皮肤”）——不用调整结构，不用改名，文件也不会被改动（这类皮肤不能推送，但仍然可以拉取）。（如果 Customizer 插件本身还装着，请把它卸载：两个模组会修改同样的贴图，互相冲突。）

通过模组管理器安装的 Customizer 皮肤也一样能用——它们会被装到 BepInEx/plugins/ 下，Customizer 从来不会去那里找，但 Stitchwork 能通过创作者打包在 zip 里的 active.txt 文件认出它们。它们的衣服图标提示是“plugins/ 下的 Customizer 皮肤，不在 Customizer 自己的文件夹中”。如果某个通过模组管理器安装的皮肤没有出现，请检查它的文件夹根目录下有没有 active.txt——没有的话就新建一个空文件，然后点击重新扫描。

Stitchwork 也能读取扁平结构的皮肤。有些 Thunderstore 皮肤把所有文件都放在同一个文件夹里，没有任何子文件夹。Stitchwork 会从这个文件夹中载入 sactx-*.png 整图、以贴图名称命名的贴图文件，以及视频文件。有一个限制：扁平结构里的 atlas0.png 只说明了是哪张 tk2d 图集，却没有说明它属于哪个集合，所以 Stitchwork 不会应用它——日志会记下每个被跳过的文件。想用这部分美术，请把它移到 Spritesheets/[Collection]/[TextureName].png。

第七步——剩下的动画，以及更多内容

你刚才只修改了一帧，而这段动画包含好几帧。使用预备 N 个待编辑的精灵图（在控制台整段动画分组的“逐帧”下），就能一次拿到所有帧。它会把每张不同精灵图的原版 PNG 复制到 Sprites/Knight/atlas2/，保留你已有的文件，然后打开文件夹。复用的帧只会复制一次。如果想让整段待机动画保持一致，就给每一帧的披风都涂上同样的亮蓝色。每个文件名就是这张精灵图在游戏中的名称（idle0000、idle0001……）；只要名称一致，Stitchwork 就能找到它。

如果要处理整段动画，更强大的方式是动画工作流画布（B6）：所有帧都会放到同一块对齐好的洋葱皮画布上，编译回会把画布重新拆分回去，位置和锚点标签都会自动帮你处理好。如果只是修一两张精灵图，逐帧导出依然够用。

整个框架都是同一种模式——找到名称，把文件放到对应的路径上：

  • 音效 → Sounds/{ClipName}.ogg
  • 文本 → 对话编辑器会自动帮你生成 YAML 文件（文本与对话）
  • 视频 → Videos/{CinematicName}.mp4

你已经掌握了什么

  • 路径就是身份。放在正确 Sprites/Collection/Material/Sprite.png 路径下的 PNG，本身就是替换资源——无需导入，无需编译。
  • 热重载片刻后就能显示保存的结果。只有换上新版本的 Stitchwork，以及少数标着 需重启 的设置，才需要重新启动游戏。
  • 资源包本质上只是一个文件夹。多个资源包可以同时存在，由资源包管理器决定哪些启用、哪些覆盖其他资源。
  • 身份卡才是名称的唯一可信来源——额外记忆点：游戏内部把大黄蜂（Hornet）叫做 Knight。
