B7 Sprite Paths Reference

referencecreator5 min read
For Stitchwork 0.9.1 · Last edited: 2026-10-22

Sprites · reference.
Every place a sprite file can go, and what each place is for.
Keep it open while you build.

You'll be able to: pick the exact path for any sprite replacement in two questions, and recognize all six paths at a glance.

Pick a path in two questions

  1. tk2d or T2D? — These are the game's two sprite systems. Animated characters and enemies are almost always tk2d. HUD, menus, effects and some ability art are usually T2D (Texture2D), but some HUD frames, such as the silk orb's frame, are tk2d. Graphics tells you (B2): a sprite in the Animation mode is tk2d, in T2D Textures it's T2D, and the world-pick card names the kind.
  2. New art or a ported sheet? — New art → individual (the recommended path). A finished sheet from Custom Knight Creator (CKC) or older work → whole atlas (B3, the porting path).
IndividualWhole atlas
tk2dSprites/{Coll}/{Mat}/{Sprite}.pngSpritesheets/{Coll}/{Mat}.png
T2DSprites/T2D/{Atlas}/{Sprite}.pngSpritesheets/T2D/{Atlas}.png

Plus two advanced paths: one for a name collision, one for per-clip art (both below).

Each path on this page starts inside a pack's Stitchwork/ folder, or inside <Game folder>/Stitchwork/ for your working folder (Pack Folder Structure).

The six paths

1 · Individual tk2d sprite — the common case

Sprites/{CollectionName}/{MaterialName}/{SpriteName}.png

One frame of an animated character/enemy/UI element. Example — a frame of Hornet's idle (remember the game calls her Knight):

Sprites/Knight/atlas2/idle0000.png

Knight = collection, atlas2 = material (the atlas sheet), idle0000 = sprite. Read all three off the identity card in the Animation console (B2). Full walkthrough: B1. Can be larger than vanilla — see anchors, below.

2 · Whole tk2d atlas

Spritesheets/{CollectionName}/{MaterialName}.png

A complete sheet as one PNG. It must match the original's layout exactly, at its size or a uniform scale of it, because it goes in place of the original. Use it to port CKC output and older sheet-based skins, not for new art → B3.

Spritesheets/Knight/atlas2.png

3 · Individual T2D sprite

Sprites/T2D/{AtlasName}/{SpriteName}.png

One sprite in the Texture2D system (HUD/UI/effects). {AtlasName} is the clean name (sactx-… prefix and hash stripped). → B4.

Sprites/T2D/Hornet/health_pip.png

A flat file, Sprites/T2D/{SpriteName}.png (no atlas folder), also loads. It matches that sprite name in every atlas, so use #3 when two atlases share the name (B4 › Flat files). The Pack Doctor report flags flat files with an informational note for exactly this reason.

4 · Whole T2D atlas

Spritesheets/T2D/{AtlasName}.png

An entire T2D atlas, in place, at exactly the original width and height (stricter than #2, which allows a uniform scale). Dump → Atlas in T2D Textures gives you a reference map of the sheet. → B4.

5 · Instance-specific tk2d sprite — advanced

Sprites/{CollectionName}/{VanillaTextureName}/{SpriteName}.png
Spritesheets/{CollectionName}/{VanillaTextureName}.png

For a rare case: two collections that share a name but hold different art. This page calls them copies. Path #1 reaches every copy, and usually that is what you want. Use this path only when you want to give the copies different replacement art. If you're unsure whether you need it, you don't.

How you'll know. Stitchwork tells you. When you have files for a collection name that two collections use, the log prints this warning the first time that both copies have loaded:

[SpriteLoader] Duplicate collection name '{CollectionName}' (instanceId …,
N definitions, dataGuid '…'). Use the vanilla texture name as the folder/file name
to target this instance specifically: …

The lines after it give the vanilla texture name of each material in that copy. The vanilla texture name is usually different for each copy, so put it where the material folder normally goes. The log gives these names only for the copy that triggered the warning. For the other copy, you need an external asset tool. Say the log names the copy you want prisoner_b:

Sprites/{CollectionName}/prisoner_b/idle0000.png

It works together with #1. The instance-specific path is tried first, then the material path. So you can ship both: a path #1 file as the default for every copy, and an instance-specific file for the one copy that differs.

When the texture names match too, this path can't tell the copies apart either, and a file reaches both. The Slab Prisoner enemy and the Slab Prisoner NPC are such a pair: both are Slab Prisoner Cln, both use atlas0. Per-sprite files still reach the right one, because the two share no sprite names. A whole sheet lands only on the copy whose atlas shape it fits; the other copy refuses it, and the log says so.

6 · Per-clip tk2d sprite (Appliqué) — advanced

Sprites/{CollectionName}/Clips/{ClipName}/{SpriteName}.png

A file here changes the sprite in one named animation clip only. Every other clip that reuses the sprite keeps the shared replacement (or vanilla). The Clips/ folder goes in the collection folder, not in a material folder, because the frames of one clip can be on different atlas pages. The folder name is the clip's name (case does not matter), and it applies to every loaded clip with that name. Beats path #1 for that clip only. Depth: Reused Frames and Appliqué.

Anchored & precise variants

Any individual tk2d path (#1, the Sprites/ form of #5, and #6) may carry an anchor tag on the filename, used only when your replacement is larger than the vanilla slot. T2D files (#3) don't take anchors; they have size tags instead (T2D Sprites).

Sprites/{Coll}/{Mat}/{Sprite}@t.png        ← top   (@b/@l/@r/@c too; untagged = bottom)
Sprites/{Coll}/{Mat}/{Sprite}@p120_64.png  ← precise pivot (px from left, py from bottom)

Full rules — when they apply, the five presets, the precise @p form — in Bigger Art: Anchors. Whole-atlas files (#2, #4, and the Spritesheets/ form of #5) don't take anchors: a sheet keeps the original layout, so one sprite cannot get more room than its slot.

Conventions

  • Individual files and sheets together. Inside one pack, individual files draw over that pack's sheet. A sheet from a higher pack hides the individual files of the packs below it, and of your working folder, on that sheet's material (tk2d) or atlas page (T2D). The same rule applies to the Clips/ files of path #6.
  • Case-insensitive, but match the dump. Knight/atlas2/Idle0000.png and knight/atlas2/idle0000.png both load. Use the case that the dump produced. The top-level folders (Sprites, Spritesheets, …) are the exception: on Linux and Steam Deck a wrongly-cased one is ignored (Pack Folder Structure).
  • Stitchwork ignores non-matching files. It ignores hidden files (.-prefixed), system files (.DS_Store, Thumbs.db) and source files (.psd, .kra), so you can keep your layered sources next to the exported PNGs. It also ignores a file with a typo in its name: check the name when a replacement does not show.

Other asset types

This page covers sprites. For the other asset types, see: Sounds → Sounds/{ClipName}.{ext} (D1) · Videos → Videos/{CinematicName}.{ext} (E1) · Text → Text/{Sheet}/{LANG}.yml (C1) · Fonts → Fonts/_fallback/{name}.ttf and more (C2) · Recolor → Recolor/{SceneName}.txt (B9).
