C1 Text & Dialogue

introcreator10 min read
For Stitchwork 0.9.1 · Last edited: 2026-10-22

Text · for creators.
The friendliest asset type to work with — no art tools, no audio editor.
Find a dialogue line or text prompt in the Dev Hub, retype it, click Save, done.
A complete rewrite, additional translation/localization, a joke patch: all use the same workflow.

You'll be able to:
edit any dialogue, item name, or UI string in the Text tab's Editor; understand the YAML it writes;
format dialogue with the game's tags;
translate the game, or Stitchwork itself, line by line;
and ship a multi-language text pack.

Before you start:
Module A.

What you can replace

Anything the game looks up through its localization system:

  • NPC and boss dialogue
  • Item names and descriptions
  • UI prompts, tooltips, menu strings
  • Wish Board (Quests) text
  • Area, ACT, and NPC Title Cards

If it's words on screen, it's almost certainly reachable.

The easy path — let the editor write it

You can author the files by hand, but you rarely need to.
The Dev Hub's Text tab finds the string for you and writes the file:

  1. Open the Text tab (key 4, or its pull tab at the top of the screen).
    Two panels open: Recent at the left and Editor at the bottom right.
    Recent lists each line that the game reads, newest first, by its sheet and key. Make the game show the line that you want. The line appears at the top of the list.
  2. Click the line, for example Wanderers.HUNTER_FAN_GREET. It opens in the Editor.
  3. Edit the text. To add a page break, click a tag button under the text (the tags).
  4. Save.
    Stitchwork writes the YAML to your working folder at Text/{Sheet}/{Lang}.yml.

That's the whole loop.
Note that the change shows the next time that line is triggered. If the line is on screen now, close it and trigger it again.

Editor edits always win. For text, your working folder beats every pack, and the Editor saves to the working folder. For most other asset types, a pack beats the working folder. See Priority & Conflicts.

Recent and the Editor, in detail

Finding a line

  • Recent keeps the newest 15 rows. Older rows fade out over 10 seconds (config TextLogMaxVisible and TextLogDuration). Clear log empties the list.
  • Search text looks in the sheet, the key and the text. It also searches your loaded override files. Matches there sit under "Loaded overrides, not seen this session".
  • Open a line by name: type its Sheet and Key at the top of the Editor, then click Open (or press Enter in the Key field). The text starts as the game shows it now. If the game has no line with that sheet and key, the field starts empty.
  • With an unsaved edit, a click on another line asks first: Save, then open or Discard my edit. A right click cancels.
  • A click on the open line in Recent reads it again, when you have no unsaved edit.

Editor buttons

  • Save writes the file that the Editor shows after the line's name, for example → EN.yml (which language). If the game language changes before you save, Save still writes the file of the language that you edited in. While your edit is not saved, the Save button reads Save *.
  • The folder button beside the file name shows the file that the line comes from: the file in your working folder, or else the pack file that the game reads. For a line that has no override, the button opens the folder where Save writes.
  • Revert drops your edit.
  • Delete override removes your line from the working folder's file. Click it twice: the first click changes it to "Click to delete".
  • Translate this line opens the line in the Translate mode.

What it writes — the YAML

The Editor writes a small, readable file. The shape below helps when you edit a file by hand or check one.
Knowing the shape helps when you hand-edit or review:

# Stitchwork text replacement
KEY_NAME: "Replacement text"
ANOTHER_KEY: "Supports \"escaped quotes\" if needed"
  • # starts a comment.
  • One KEY: "value" per entry.
    Keys are case-sensitive. Type each key exactly as Recent shows it. Spaces around a key do not count.
  • Values are quoted strings.

The path:

Text/{SheetName}/{LANG}.yml

SheetName is the localization sheet (Wanderers, Prompts, Quests, …);
LANG is a language code (EN, ZH, FR, JA, …).

Formatting dialogue — the tags

In-game line breaks and page turns come from tags, not from how the text looks in the file:

  • <page> — page break; the text shows in a new NPC dialogue box (button: <page> NPC)
  • <hpage> — page break; the text shows in a new Hornet dialogue box (button: <hpage> Hornet)
  • <br> — line break within one page (button: <br> line break)
  • <page=S>, <page=T>, <page=L>, <page=B>, <page=M> — purpose unknown, possibly page styles that the game no longer uses. They are under the Editor's More.

Insert these with the Editor's tag buttons. A button puts the tag at the cursor. A break tag also starts a new line in the Editor's view.

Editor display ≠ saved file.
The editor starts a new display line before each tag. In Chinese or Japanese text, it also breaks a long line after a sentence end (。, ！, ？). It never breaks after a Latin ., ! or ?. You can also press Enter to lay out your text in the Editor. Enter only wraps the view: it adds no space and no break. Use <br> for a break.
None of these line breaks reach the YAML or the game; the hint under the text says "Tags start a new line · line breaks are stripped on save".

Escaping — the three rules

The Editor escapes quotes and backslashes when it saves. Use these rules only in a file that you edit by hand. Inside a quoted value:

  • A double quote → \"
  • A backslash → \\
  • A newline → don't. Use <br>. A real newline in the YAML breaks the entry, and the game reads only up to the break.

Multiple languages

To translate or rewrite across languages, ship one YAML per language under each sheet:

Text/Wanderers/
  EN.yml
  ZH.yml
  JA.yml

The game reads the file of its current language, so a player who changes the language in the game sees the overrides of that language. The Editor works in the game's active language. If the game is set to English while you write ZH text, Save writes EN.yml. The Editor shows the file name before you save (→ EN.yml).
Two ways to write the right file:

  • Set the game language first, in the game's own options menu.
  • Use the Translate mode with the Game source. It writes any language, and the game can stay in its current language.

Translate mode

The switch at the top of Recent reads Game text | Translate. Translate turns the two panels into a workbench for translators: a list of lines at the left, and a Translation panel with the reference and your text side by side. The bar at the top of the Translation panel selects the text that you translate: Game or Stitchwork. The Editor's Translate this line opens its line here, in the Game source.

Game — the game's own text:

  • From sets the reference language. The arrow points to the target, the language slot that you write.
  • Each line saves to Text/<Sheet>/<LANG>.yml in your working folder. That is the same file the Editor writes.
  • The bar shows Live in game when the game runs in the target. If not, it shows "Game runs in …" and a Play in … button that switches the game's language.
  • A language that the game does not have goes over one of its slots. Pick the slot you will play in (often EN), and keep EN as the reference. The reference always shows the game's own line, so it stays the original English after you save over EN.

Stitchwork — the text of Stitchwork's own interface:

  • Pick a language file, or New language…. Type a Code and a Name, then click Create (the button names the new file).
  • Your file goes to Lang/<code>.yml in your working folder (by default <Game folder>\Stitchwork\Lang\). Stitchwork reads it over the file it ships for that language.
  • Show in the UI shows that language in Stitchwork while you work.

Working through the list

  • The filters are Review (drafts that wait for you, for example machine translations), To do (no translation yet, or sent back), and All. A draft is a line with # draft after its closing quote.
  • The main button changes with the line. Save writes your edit. Pass accepts a draft as it is. Keep (Game only) marks the game's line as right, with no override; the file gets a # kept: comment. If a game update changes that line, it comes back to To do.
  • When another line follows in the list, the button reads "… and next" and opens that line.
  • On a draft, Needs revision sends it back, with an optional note.
  • Remove override (Game only) deletes your line from the file. Click it twice.
  • The chips under the text check the tags and placeholders. Use each tag and placeholder that the reference has, and add no other. In game text, use each one as many times as the reference does. A click on a chip inserts it.
  • In the text field, Ctrl+Enter clicks the main button. Ctrl+↑ and Ctrl+↓ move through the list.
  • The folder button opens Text/ or Lang/ in your working folder, so you can send your file from there.

Testing a line that only plays once

A first-meeting greeting or a one-shot cutscene line is awkward to verify — in vanilla, you'd have to start a new save to proofread it again.
The practical fix is DebugMod's savestates:

  1. Make a savestate just before the conversation.
  2. Edit your line.
  3. Restore the savestate.
  4. Watch the line again in context, as often as you like.

Savestates also work for dialogue that the FLAGS strip cannot track.
See Testing With Savestates.

The FLAGS strip

The flag editor is the FLAGS strip at the right edge of the Editor. It lists the PlayerData flags (the game's saved variables) that changed this session, with the value that each one had first (orig:). Many conversations record their progress in these flags. You can set a flag by hand, and Reset all sets every flag back. Filter flags and Story only make the list shorter.

Moving your text into the pack

The Editor saves into the working folder, not into your pack. When the text is ready, click Choose a pack for your text at the top of the Editor and pick your pack. The bar then shows Pack text and the pack's name. Stitchwork keeps this choice after a restart. Click Compare with working folder. The review takes the Editor's place and lists every difference:

  • Changed — both sides have the key with different text. Pick Working folder, Pack, or Custom (a field that starts from the pack's text). Take all: working folder and Take all: pack decide every key at once.
  • New sheets — whole files the pack has no sheet for. Tick the ones that belong to this pack. They are ticked by default when no other pack has text.
  • New in the working folder — keys the pack does not have yet. Push carries them into the pack.
  • Only in the pack — Push leaves them; Pull copies them into the working folder.
  • Identical — the pack has these already. Push removes the working-folder copies.

The buttons:

  • Push {n} → pack writes the ticked and resolved text into the pack, then moves those keys out of the working folder, so the pack's copy is the one the game reads. Customizer packs are read-only, so Push is off for them.
  • Pull {n} ← pack is the mirror: it copies the pack's text into the working folder for editing.
  • Discard closes the review.

Undecided keys stay on both sides. Before Push or Pull changes a folder tree, it copies that tree to a timestamped backup folder beside it.

With an unsaved edit, Compare asks first: Save, then compare or Compare without it.
