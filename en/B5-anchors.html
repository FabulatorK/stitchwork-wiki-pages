B5 Bigger Art — Anchors

intermediatecreator6 min read
For Stitchwork 0.9.1 · Last edited: 2026-10-22

Sprites · for creators.
Your art can be bigger than the original: a longer needle, a taller crest.
The anchor decides where the extra room goes.

You'll be able to: enlarge a sprite without it drifting out of place, pick the right anchor, set it from the filename or in Graphics, and use the precise pivot when no preset fits.

Before you start: B1. This only matters once a replacement outgrows its slot — for same-size art, none of this applies.

Editing an animation? The Animation Canvas does this page's work for you: Compile places every frame and writes the anchor tags itself. Hand-author tags for single or static sprites, or when you work outside the canvas.

Why an anchor is needed at all

Say the vanilla sprite is a 64×96 head, and you draw a 128×128 one. Stitchwork enlarges the 64×96 slot of the vanilla sprite to fit your art — but it has to decide where the bigger slot sits relative to the body:

  • Bottom (the default): the bottom edge, at the neck, stays in place. The art grows up and to both sides.
  • Center: the art grows the same amount in all directions, so the head also grows down past the neck.
  • Top: art hangs from the top edge and grows down.

With the wrong anchor, an enlarged sprite moves off its body.

When it matters (and when it doesn't)

  • Only for replacements LARGER than the vanilla slot. That's the whole feature.
  • Same-size or smaller → the tag is inert. The slot never expands, so there's nothing to anchor. (Graphics still lets you set one; it just has no visible effect until the art is enlarged.)

The five anchors

Stitchwork has five anchors and no corner anchors. The axis that an anchor does not name always centers:

              top  (@t)
  left (@l)  center (@c)  right (@r)
            bottom (@b)
  • bottom — the default. You do not need to type it, because an untagged file is bottom-anchored. Right for anything that stands on the ground.
  • center — for art that radiates from a point (effects, symmetric items).
  • top — for things that hang (a light beam, a banner).
  • left / right — pin that edge, grow away from it.

Need a corner? Pick the axis that matters most; the other centers.

Setting an anchor — the filename tag

The anchor lives in the PNG file name, as a trailing @x:

Sprites/{Collection}/{Material}/{Sprite}@t.png
File nameAnchor
crest@t.pngtop
crest.pngbottom (default)
crest@b.pngbottom (explicit — same as untagged)
crest@l.png / crest@r.pngleft / right
crest@c.pngcenter

Stitchwork strips the tag when matching the file to a sprite, so crest@t.png still replaces the sprite named crest — the tag only steers the anchoring of an enlarged replacement.

Don't ship two files for one sprite. If crest.png and crest@t.png are in the same folder, they conflict. Stitchwork always uses the name that sorts first, so crest.png wins and the @t file has no effect. Delete the file that you do not want.

Setting an anchor in Graphics

  • Open Graphics (3) in Animation mode. Select the object and the clip. Go to a frame that uses your sprite. In the console, This sprite has an Anchor row: five icon buttons (top, bottom, left, right, center). Hover over a button to see its name. The lit one is your file's current anchor; untagged counts as bottom.
  • When you click a button, Stitchwork renames your PNG in the working folder to carry the matching tag. bottom removes the tag. For example, top renames crest.png to crest@t.png. The sprite reloads a moment later, without a scene reload.
  • If a file with the new name already exists, Stitchwork does not rename your file. The line under the row says "Can't set the anchor: … already exists. Remove the duplicate first."

The row reminds you that the anchor affects enlarged replacements only. It is disabled in two cases, and the line under it says why:

  • No replacement file yet: Edit creates one; then it can be anchored.
  • Supplied by pack: an active pack's file wins for this sprite, and the buttons only rename files in your working folder.

The buttons work on plain and preset-tagged names (@t @b @l @r @c). On an @p file (precise pivot), no button is lit, and a click replaces the precise pivot with that preset. The buttons do not change a file in an instance-specific folder or in Clips/; rename those by hand.

The precise pivot — @p<px>_<py>

The five presets are shorthands for the most common placements. Some placements need a different amount of growth on each side, for example +50 px on top but only +25 on the bottom. The presets cannot do this. Use the general form:

Sprites/{Collection}/{Material}/{Sprite}@p120_64.png

@p<px>_<py> places your replacement so that the pixel at (px from the left, py from the bottom) lands on the vanilla sprite's pivot. The pivot is the point where the game puts the object. The tag has an effect only when your PNG is larger than the vanilla sprite.

You rarely write this tag by hand. The Animation Canvas compile writes an @p tag on each frame that you made bigger than its slot, so the frame stays in its exact place. Write the tag by hand for an asymmetric enlargement outside the canvas.

Packs and the working folder

  • Packs ship the tagged name directly — a pack author just names the file {Sprite}@t.png inside …/Sprites/{Collection}/{Material}/.
  • The Anchor buttons act on your working folder (<Game folder>/Stitchwork/Sprites/…) — they never rename files inside other people's pack folders.
  • If several packs supply the same sprite, the usual priority order decides which file (and tag) wins.

Migrating from anchors.txt

Older packs used a Sprites/{coll}/{mat}/anchors.txt sidecar. It's no longer read — Stitchwork logs a one-time warning if it finds one, and the Pack Doctor report flags it. To migrate: for each spriteName = anchor line, rename that sprite's PNG to carry the matching tag, then delete anchors.txt. The old nine points collapse to five — for a corner, choose the axis that matters most; *-center → that side; plain center → @c; bottom-center → untagged.

Troubleshooting

  • "My enlarged sprite is positioned wrong." Check the tag on the file name. Look for an untagged copy of the same sprite in that folder, because the untagged file wins. Make sure that the file is at the correct collection and material path.
  • "I set an anchor but nothing happened." The anchor has an effect only when the replacement is larger than the slot. With same-size art, the tag has no effect.
  • "Graphics refused to set my anchor." A file with the target tagged name already exists. Remove the duplicate, then set it again.
  • "The Anchor buttons are grayed out." Read the line under them: either you have no replacement file yet, or a pack supplies the sprite.
  • "My old anchors.txt stopped working." Stitchwork no longer reads it; the filename tags replace it. See Migrating from anchors.txt above.
