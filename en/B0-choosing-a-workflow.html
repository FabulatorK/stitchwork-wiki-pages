B0 Choosing a Workflow

introcreator6 min read
For Stitchwork 0.9.1 · Last edited: 2026-10-22

Graphics · start here.
One question decides everything downstream:
which sprite system draws the thing you want to change?
This page is the map — the two systems, how to choose an editing route, and exactly what the finished files look like.

Silksong draws its art with two different sprite systems, and they are different enough that Stitchwork gives each its own tools:

  • tk2d — the animated world. Hornet, enemies, bosses, most things that move. Sprites live in shared atlases managed by the 2D Toolkit engine.
  • T2D (plain Unity Texture2D) — the trouble child, which does everything else, and it's a lot: attack effects, particles, UI, menus, and static scene props (a busy scene can hold over a thousand of these). It even animates some of it, with Unity's own Animator instead of tk2d.

Not sure which one your target is? Don't guess — press P and point World Pick at it. The pick lands you in the right tool automatically.

The map

tk2d: individual sprites or animation canvases

Choose one of the two routes below: edit sprites one at a time, or use the animation canvas workflow for a whole clip. Both routes can give one clip its own art for a shared sprite (Appliqué, below). The game can stay open while you edit.

Individual sprite editing

The full walkthrough is Starting a Skin Pack. Open Graphics (3, or the Graphics pull tab at the top edge of the screen). Choose Animation in the Library panel. Pick your target with Pick object in world (World Pick), or choose it from the list under "Or choose one the game has animated this session:".

Click a clip. Choose a frame on the frame strip in the Preview panel. Then click Edit (new from vanilla) in the This sprite group of the console, under the clip list. Once your file exists, the button reads Edit (opens your file). Paint and save: a moment later, the game shows your art. Repeat, sprite by sprite, until the thing looks right. The Animation Mode tours every control.

Animation canvas workflow (recommended for clips)

The full guide is Animation Canvas. Individual editing changes an animation one sprite at a time. Each frame's sprite has its own crop and position on the atlas. So it is hard to align art across frames by eye, and the animation can look shaky. The animation canvas workflow removes this problem. Its controls are in the console's Whole clip group. Step 1, Open canvas, hands you a padded canvas of the same size for every frame in the clip. The frame pivots align, so you can use onion-skin layers while you paint. Step 2, Compile back, converts the edited canvases into per-sprite files, with placement tags for bigger art.

If you change a whole clip, start here. Then you do not enlarge each frame by hand. The honest trade: your loop becomes save → Compile back → see instead of save → see. Compile back writes only the frames that you changed, and it backs up each file that it replaces. B6 has the batch tools and the other details.

Optional: bigger art and Appliqué

Optional for individual editing: bigger art (Anchors): when a single replacement needs more room than the vanilla sprite had, make the canvas bigger and tell Stitchwork how to place it — a filename tag like @t (top) or the precise @p120_40. The atlas grows to fit. Still the same loop; you've only changed the file you save. The Anchor row in This sprite sets one of the five preset anchors for you: it renames your file (B5).

Optional for either route: Appliqué (per-clip art): tk2d reuses frames: one sprite can appear in several clips, so a change to it changes all of them. When that's not what you want, Appliqué gives one specific clip its own art via the Clips/<ClipName>/ folder. Detach for this clip (in This sprite) and Compile as Appliqué (in Whole clip) write that folder for you. The folder matches by clip name, in every loaded animation library. So a clip with the same name in another library (a crest's, for example) also gets this art. The animation canvas alone does not give a clip its own art.

T2D: find it, then the same loop

T2D sprites are not harder to edit. They are harder to find.

Only a few files still need a dumped reference: the ones that the live finders do not show. Try these three finders in order:

  1. World Pick — press P and point at the thing on screen; a T2D hit opens T2D Textures with it selected. To pick a fast effect, freeze time with a companion mod first.
  2. T2D Textures (Graphics → the second mode in the Library) — every T2D texture in memory, with previews. You can search by the clean name, the short atlas name such as Hornet (B4).
  3. Your dump folder — for things that are hard to catch live (Dumping).

Once found, the loop is the one you already know. Select the sprite. Click Edit (new from vanilla), or the small Edit on its row. Stitchwork writes the vanilla sprite into your working folder and opens it. Paint, save, hot reload: one PNG per sprite, at Sprites/T2D/<AtlasName>/<sprite>.png. The buttons in the Dump row are different: they write only to Dumps/, which Stitchwork never loads.

Atlas, in that Dump row of the Preview panel, is the reference tool. It writes the whole sheet to Dumps/, as a plain image. It shows what lives together and how much room a slot has. Keep it open beside your editor; do not edit it and ship it. Sheet layouts and names change with game updates. After an update, your file stops matching, and no message tells you (B3).

Not a workflow: spritesheets

No route on this page ends in a spritesheet. On a sheet, you must align frames by eye across scattered crops: the problem that the animation canvas removes. Community tools exist to get away from drawing on sheets: Custom Knight Creator (CKC) with its per-animation preview, and the animation canvas with its uniform frames.

The Spritesheets/ tier still loads, and loads well — because it's the porting door. If you have prior work from CKC (a standalone skinning tool we happily coexist with) or an older sheet-based skin, it drops in and runs. That story, including the exact-match rule and the T2D caveats, is Porting Prior Work.

Take the library with you

One more tool that isn't a workflow but serves them all: the full-game dump (Dumping) exports the entire asset library to disk. Creators use it to work away from the game — copy the files you intend to change onto a tablet, paint on the couch or the train, drop the finished PNGs into your working folder when you're back. The dumped files have the same names and folders as replacement files. So you can copy a changed file into your working folder with no renaming.

Where they all end

Every workflow finishes in your working folder (by default <Game folder>/Stitchwork/, beside Packs/; a mod-manager update never touches it), where hot reload picks your files up a moment after you save. The working folder ranks below every active pack: when a pack has its own file for the same sprite, the pack's art shows. When the art is done, choose your pack as Target pack: in the Overview panel (2). Click Push, which copies your working files into the pack (Pull copies a pack's files back to you; Push and Pull explains both). Then click the stethoscope button on the pack's card in Packs to run the Pack Doctor. Distributing Your Pack covers the rest. The full path grammar for every tier lives in Sprite Paths.
