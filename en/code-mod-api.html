The API for Code Mods

referencecreator6 min read
For Stitchwork 0.9.1 · Last edited: 2026-10-22

Reference · for mod authors.
A code mod can tell packs what happens in the game.
The mod publishes a yes/no fact, and a pack names it.
Pack creators: the pack side shows how to name a mod's condition in conditions.json.

You'll be able to: publish a condition from your mod, name it in a pack's rule sets, and read the log when a call fails.

What the API does today

One part of the API works today: conditions. Your mod publishes a condition: a name and a function that returns true or false. A pack names the condition in one of its rule sets: a folder of extra files. While the condition is true, Stitchwork shows that set.

For example, a mod that adds binds publishes BindActive. A pack shows a glowing cloak only while a bind is active. The pack needs no code, and the mod needs no art.

Rule sets are a preview feature (Conditional Activation). The other parts of the API are not built yet: see Not built yet.

The contract

These rules hold for every version of the API:

  • The class is Stitchwork.StitchworkApi, in Stitchwork.dll. Its full name never changes.
  • StitchworkApi.ApiVersion is 1. A new version only adds members. An existing member never changes its shape or its meaning. A breaking change gets a new member name and a new version number.
  • The parameters are strings, bools and Func<bool> only. Thus your mod can call the API by reflection, with no reference to Stitchwork's types.

ApiVersion is a constant, so a mod with a hard reference keeps the number that it was built with. To read the installed version, read the field by reflection:

typeof(StitchworkApi).GetField("ApiVersion").GetValue(null)

The members

The members are in StitchworkApi.Conditions.

MemberWhat it does
bool ReadyTrue when Stitchwork has started. False when Stitchwork is inert, for example when Patchwork is installed too. After Stitchwork starts, the value does not change during the session.
bool Register(string owner, string name, Func<bool> predicate)Publishes the condition owner:name. A second call with the same owner and name replaces the predicate.
bool Unregister(string owner, string name)Removes one condition. A pack that names it reads false from the next check. Returns true when the condition was registered.
void Notify(string owner, string name)Tells Stitchwork that the value changed. Stitchwork then checks the sets in the next frame.
int RemoveAll(string owner)Removes all the conditions of your mod. Returns the number that it removed.

The arguments:

  • owner must be your mod's BepInEx plugin GUID. In your plugin class, Info.Metadata.GUID gives it. The GUID must not contain :.
  • name must contain only letters, digits and _.
  • predicate must not be null.

The rules

  • Call the API from the main thread only. A call from another thread does nothing and returns false.
  • No exception comes back to your mod. A bad call returns false, 0 or nothing, and the log gets one warning. When Stitchwork is not ready, a call returns false, and the log gets nothing.
  • Keep the predicate fast, with no side effects. Stitchwork reads it a maximum of one time in each frame.
  • A predicate that throws is turned off. One log line names its owner. The condition reads false until your mod calls Register again.
  • Call RemoveAll when your mod stops, for example in OnDestroy. BepInEx cannot unload a plugin, so your mod must remove its own conditions.

When Stitchwork reads the value

Stitchwork reads your predicate only while an enabled pack has a set that names it. Then it reads the predicate when a room loads, every 2 seconds, and in the next frame after a Notify. Stitchwork never reads a condition that no enabled pack names.

So call Notify each time the value changes. The call is cheap.

Example: a hard reference

Use this form when your mod needs Stitchwork. Add a reference to Stitchwork.dll.

using BepInEx;
using Stitchwork;

[BepInPlugin("example.bindmod", "Bind Mod", "1.0.0")]
[BepInDependency("Stitchwork")]
public sealed class BindMod : BaseUnityPlugin
{
    private bool _binding;

    private void Awake()
    {
        if (!StitchworkApi.Conditions.Ready) return;
        StitchworkApi.Conditions.Register(Info.Metadata.GUID, "BindActive", () => _binding);
    }

    private void OnBindChanged(bool on)
    {
        _binding = on;
        StitchworkApi.Conditions.Notify(Info.Metadata.GUID, "BindActive");
    }

    private void OnDestroy() => StitchworkApi.Conditions.RemoveAll(Info.Metadata.GUID);
}

[BepInDependency("Stitchwork")] makes BepInEx start Stitchwork before your mod. Thus Ready is already true in your mod's Awake. (Stitchwork is the BepInEx GUID of Stitchwork.)

Example: reflection

Use this form when your mod must also run without Stitchwork. Your mod needs no reference to Stitchwork.dll. We ran this form in the game. We compiled the hard-reference example above, but we did not run it in the game.

using System;
using System.Reflection;
using BepInEx;

[BepInPlugin("example.softbindmod", "Soft Bind Mod", "1.0.0")]
[BepInDependency("Stitchwork", BepInDependency.DependencyFlags.SoftDependency)]
public sealed class SoftBindMod : BaseUnityPlugin
{
    private bool _binding;
    private MethodInfo _notify;

    private void Awake()
    {
        var conditions = Type.GetType("Stitchwork.StitchworkApi+Conditions, Stitchwork");
        if (conditions == null || !(bool)conditions.GetProperty("Ready").GetValue(null)) return;
        var register = conditions.GetMethod("Register", new[] { typeof(string), typeof(string), typeof(Func<bool>) });
        _notify = conditions.GetMethod("Notify", new[] { typeof(string), typeof(string) });
        register.Invoke(null, new object[] { Info.Metadata.GUID, "BindActive", (Func<bool>)(() => _binding) });
    }

    private void OnBindChanged(bool on)
    {
        _binding = on;
        _notify?.Invoke(null, new object[] { Info.Metadata.GUID, "BindActive" });
    }
}

The soft dependency keeps the same start order when Stitchwork is installed, but it does not make Stitchwork necessary. Without Stitchwork, Type.GetType returns null, and the mod continues without the condition.

The pack side: a mod condition

A pack names a mod's condition as owner:name. The owner is the mod's BepInEx GUID, and it can contain dots and dashes. The name is the text after the last :. Write it in the pack's conditions.json, beside pack.json, in one of two forms.

As a named condition. A set then uses the condition by its name:

{
  "conditions": { "BindActive": { "mod": "example.bindmod:BindActive" } },
  "sets": [
    { "name": "Bind", "when": "BindActive" }
  ]
}

Directly, as a set's when:

{
  "sets": [
    { "name": "Bind", "when": "example.bindmod:BindActive" }
  ]
}

The set's files go in Sets/Bind/, laid out like a pack:

MyPack/Stitchwork/
  Sprites/…              ← the pack's own files
  Sets/Bind/Sprites/…    ← only while the mod's BindActive is true

A condition that no installed mod publishes reads as false. Thus the set stays off, and the rest of the pack works without the mod.

To find a mod's condition names, read the mod's README, or ask its author. To see which conditions the mods published, search BepInEx/LogOutput.log for registered the condition.

For the full format of rule sets, and for what shows when two sets are on, read Conditional Activation.

The log

Stitchwork writes these lines to BepInEx/LogOutput.log. Each warning shows one time in a session for the same case.

WhenThe line
The call worked[StitchworkApi] <owner> registered the condition <owner>:<name>
A bad owner[StitchworkApi] Register: the owner must be the caller's plugin GUID (got '<owner>').
A bad name[StitchworkApi] Register: <owner> passed '<name>'; a condition name holds letters, digits and _ only.
A null predicate[StitchworkApi] Register: <owner> passed a null predicate for <name>.
Not on the main thread[StitchworkApi] Register was called by <owner> off the main thread; it did nothing. Call it from Unity's main thread.
A predicate threw (an error, one time for each registration)[RuleSets] the predicate '<owner>:<name>' of <owner> threw and is now off: <ExceptionType>: <message>
A pack names a condition that no installed mod publishes (a warning, one time for each key)[RuleSets] no mod provides '<owner>:<name>'; it reads as false

Unregister and Notify write the same warnings, with their own names in place of Register.

Not built yet

These parts of the API are planned. They have no date.

  • Packs and events. A mod will list the packs, turn a pack or a set on or off for the session, and apply the changes one time. An event will tell a mod when a reload is complete, and when a set changes. These parts are not built, and their shape can change.
  • Instance skins. One object gets its own skin, for mods such as Architect. The members exist, but they do nothing yet. StitchworkApi.InstanceSkinsReady is false, and ApplyInstanceSkin returns 0 and logs one warning. Your mod can test InstanceSkinsReady at startup.
